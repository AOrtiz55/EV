What is Next.js?

React is a JavaScript library for building user interfaces. It lets you break a webpage into small reusable pieces called components. Each component is just a function that returns HTML-like code called JSX.

Next.js is a framework built on top of React. It adds things React alone does not give you:

File-based Routing
Your file path = your URL
Server-side Code
Run logic before the page loads
Font Optimization
Fonts served from your own server
Code Splitting
Only loads JS the page needs
App Router
Modern way to structure Next.js
Server Components
Components that run on the server
💡

App Router vs Pages Router: Older Next.js projects used a pages/ folder. The newer App Router uses app/. We use App Router because it is the current standard and supports the latest React features like Server Components.

📁

Why components/? React is all about breaking UI into small, reusable pieces. Instead of one giant file (like mockup.html), we split each visual section into its own file. When something breaks, you know exactly which file to look in. And you can reuse a component in multiple places.

📦

Why lib/? lib/ holds code that is not a visual component. Types and data don't render anything — they just describe information. When you connect a real backend later, you swap out the contents of lib/data.ts and all components continue to work unchanged.

Core React Concepts You Will See Everywhere

Components

A component is a function that returns JSX. JSX looks like HTML but it's actually JavaScript. By convention, component names start with a capital letter.

TSX
// This is a component — a function that returns JSX
function Greeting() {
  return <p>Hello, world!</p>
}

Props

Props (short for properties) are how you pass data into a component from its parent. Think of them like arguments to a function. The parent decides what values to send; the child just receives and uses them.

TSX
// Component accepts a "name" prop
function Greeting({ name }: { name: string }) {
  return <p>Hello, {name}!</p>
}

// Parent passes the prop
<Greeting name="Aaron" />

State — useState

State is data that can change over time. When state changes, React automatically re-renders the component to show the new value. useState always returns two things: the current value, and a function to update it.

TSX
import { useState } from 'react';

function Counter() {
  // count = current value, setCount = update function
  const [count, setCount] = useState(0); // starts at 0

  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}

useCallback

useCallback memoizes a function — it prevents the function from being recreated on every render. Use it when you're passing a function as a prop to a child, so the child doesn't re-render unnecessarily.

TSX
const handleClick = useCallback(() => {
  doSomething();
}, []); // [] = only create this function once

useRef

useRef holds a value that persists across renders but does NOT trigger a re-render when it changes. Commonly used to store timer IDs (so you can clear them later) or references to DOM elements.

TSX
const timerRef = useRef<ReturnType<typeof setInterval> | null>(null);

// Store the timer ID
timerRef.current = setInterval(() => { /* ... */ }, 1000);

// Clear it later without causing a re-render
clearInterval(timerRef.current);

'use client'

⚡

In Next.js App Router, components are Server Components by default — they run on the server and cannot use browser features. When you write 'use client' at the top of a file, you're telling Next.js: "this component runs in the browser."

Rule: Add 'use client' whenever your component uses useState, useCallback, useRef, or any event handler like onClick.

TypeScript Interfaces

TypeScript lets you define the shape of your data so mistakes are caught before the app runs. A ? after a field name means it's optional. A union type like 'a' | 'b' means the value can only be one of those specific strings.

TypeScript
interface Spot {
  id: number;
  status: 'available' | 'in-use' | 'overtime'; // union type
  occupant?: string;  // ? = optional
  startTime?: string;
}

File Walkthroughs

globals.css

This file holds CSS that applies globally to the entire app. Tailwind's base styles are imported here, and we add custom classes that Tailwind cannot express on its own.

CSS
@import "tailwindcss";
📌

This line loads all of Tailwind's utility classes. Without it, classes like flex, rounded-xl, and text-sm would not work.

CSS
.glass {
  backdrop-filter: blur(28px) saturate(180%);
  -webkit-backdrop-filter: blur(28px) saturate(180%);
  background: rgba(255,255,255,0.58);
  border: 1px solid rgba(255,255,255,0.85);
  box-shadow: 0 4px 24px rgba(0,0,0,0.07), ...;
}
🪟

backdrop-filter: blur() is the CSS that creates the frosted glass effect — it blurs whatever is behind the element. The -webkit- prefix is needed for Safari browsers. rgba(255,255,255,0.58) is white at 58% opacity, which lets the blur show through.

CSS
@keyframes pulse-dot {
  0%, 100% { opacity: 1;   box-shadow: 0 0 6px rgba(34,197,94,0.8); }
  50%       { opacity: 0.5; box-shadow: 0 0 0px rgba(34,197,94,0); }
}
.pulse { animation: pulse-dot 2s ease-in-out infinite; }
💚

@keyframes defines the steps of a CSS animation (from fully visible → half visible → back). The .pulse class applies it. This creates the breathing green dot on available parking spots.

CSS
.sheet-collapsed { transform: translateY(100%); }
.sheet-expanded  { transform: translateY(0%); }
📌

translateY(100%) moves an element down by 100% of its own height — hiding it below the screen. Swapping to sheet-expanded slides it back up. This is how the "View all spots" sheet animates open and closed.

layout.tsx

In Next.js, layout.tsx is a special file that wraps every page in your app automatically. It's the outermost shell — like a frame around a picture. Every page gets placed inside it.

TSX
import { Inter } from "next/font/google";

const inter = Inter({ subsets: ["latin"], variable: "--font-inter" });
🔤

Next.js has a built-in next/font system that downloads Google Fonts at build time and serves them from your own server. This is faster than loading from Google's CDN. subsets: ["latin"] only downloads the Latin character set, keeping the file small.

TSX
export const metadata: Metadata = {
  title: "EV Parking",
  description: "EV parking spot management",
};
🏷️

Exporting metadata from a layout or page file automatically sets the browser tab title and meta description. You don't write a <head> tag yourself — Next.js handles it.

TSX
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
👶

children is a special React prop that represents whatever is rendered inside this component. When Next.js renders your home page, it wraps it in this layout and passes the page as children. React.ReactNode is the TypeScript type for "anything React can render."

page.tsx

In the Next.js App Router, any file named page.tsx inside the app/ folder becomes a URL route. app/page.tsx maps to the root URL /. If you created app/history/page.tsx, it would map to /history.

This file is the brain of the app. It owns all shared state and passes it down to child components.

⚡

Why 'use client'? This page uses useState and passes functions as event handlers, so it must run in the browser.

TSX
const [sheetOpen, setSheetOpen] = useState(false);
// Controls the full-screen "Charging Stations" sheet
// false = collapsed (hidden below screen), true = expanded

const [occupyOpen, setOccupyOpen] = useState(false);
const [occupySpotId, setOccupySpotId] = useState<number | null>(null);
// Two pieces of state for the Occupy modal:
// occupyOpen — is the modal visible?
// occupySpotId — which spot number was clicked?

const [overtimeOverlayOpen, setOvertimeOverlayOpen] = useState(false);
const [overtimeResolved, setOvertimeResolved] = useState(false);
const [nudgeLeft, setNudgeLeft] = useState(3);
// Shared between home card AND sheet — both show Spot #2
// Must live here so both instances stay in sync
TSX
const openOccupy = useCallback((spotId: number) => {
  setOccupySpotId(spotId);
  setOccupyOpen(true);
}, []); // [] = create once, reuse forever
💡

This function is passed as a prop to multiple children (ChargingStationsCard, StationSheet). useCallback with [] creates it only once. Without this, a new function would be created on every render, which can cause unnecessary child re-renders.

lib/types.ts

TypeScript types describe the shape of your data. By defining types in one place, every file that imports them gets automatic error checking — if you try to use a property that doesn't exist, TypeScript warns you before the app runs.

TypeScript
export type SpotStatus = 'available' | 'in-use' | 'overtime';
// Union type — can ONLY be one of these three values
// If you type 'Available' or 'free', TypeScript shows an error

export interface Spot {
  id: number;
  status: SpotStatus;
  occupant?: string;      // ? = optional (available spots have no occupant)
  startTime?: string;
  timeToFull?: string;
  overtimeMinutes?: number; // only overtime spots need this
}

lib/data.ts

Right now the app uses hardcoded data. When you connect a real backend later, you'll replace this file's contents with API calls. Because all components import from this file, the swap is easy — the components themselves don't need to change.

TypeScript
export const SPOTS: Spot[] = [
  { id: 1,  status: 'available' },
  { id: 2,  status: 'overtime',  occupant: 'Maria G.', overtimeMinutes: 8 },
  { id: 4,  status: 'in-use',    occupant: 'James T.', timeToFull: '42 min' },
  // ...
];
// Spot[] means "an array of Spot objects"
// export makes this available to other files that import it

Header.tsx

The header (logo, welcome text, logout, live tracking) is isolated in its own file. If you ever want to change the header — swap the user's name, add a notification bell, change the colors — you only touch this one file.

No 'use client' needed here because this component has no state. It's a Server Component that just renders static UI.

TSX

<div style={{
  background: 'radial-gradient(ellipse 70% 60% at 50% -10%, rgba(255,255,255,0.6) 0%, transparent 70%)'

MyStatsCard.tsx

Shows the logged-in user's current charging session: Spot #1, Start/Stop/Remain times, Consumption, and Charge %. It directly imports MY_STATS from lib/data.ts instead of receiving props — because there's only ever one "my stats" section.

TSX
// Instead of copy-pasting 3 identical divs, we use .map()
{[
  { label: 'Start',  value: s.startTime },
  { label: 'Stop',   value: s.stopTime },
  { label: 'Remain', value: s.remain },
].map(({ label, value }) => (
  <div key={label} className="glass-inner rounded-xl p-2 text-center">
    <p>{label}</p>
    <p>{value}</p>
  </div>
))}
🗺️

The .map() pattern is one of the most common in React. It creates an array of objects, then maps each one to a JSX element. The key prop is required — React uses it to track which item is which when the list updates. Always use a unique value for key.

TSX
// Template literal inserts the JS value into a string
<div className="charge-bar h-full rounded-full"
     style={{ width: `${s.chargePercent}%` }} />
// If chargePercent = 74, result is the string "74%"

SpotRow.tsx

There are 9 non-overtime spots. Instead of copy-pasting HTML for each one, SpotRow handles all states (available, in-use) with one component. The parent passes a spot object and the component decides how to render based on spot.status.

TSX
interface SpotRowProps {
  spot: Spot;
  variant: 'card' | 'sheet';       // home card or full-screen sheet?
  onOccupy: (spotId: number) => void; // function passed from parent
}
TSX
// && = conditional rendering: if true, render it; if false, render nothing
{isAvailable && (
  <span className="w-2 h-2 rounded-full pulse"
        style={{ background: '#22C55E' }} />
)}

// Clicking Occupy calls the function passed from the parent
<button onClick={() => onOccupy(spot.id)}>Occupy</button>
// SpotRow doesn't manage state — it reports clicks upward
🔼

Lifting state up: SpotRow doesn't know what to do when Occupy is clicked — it just calls onOccupy(spot.id) and lets the parent handle it. The parent (page.tsx) opens the modal. This pattern is called lifting state up and it's fundamental to React.

OvertimeCard.tsx

The most complex component. Spot #2 is in overtime and has: a toggle-able overlay, a nudge button, a 20-minute cooldown timer with progress bar, and a "They left" resolution flow. All this logic lives here.

⚡

Why 'use client'? This component uses useState, useRef, and useCallback — all browser-only React hooks.

TSX
// Local state — only this component cares about it
const [cooldownActive, setCooldownActive] = useState(false);
const [remainingSecs, setRemainingSecs] = useState(COOLDOWN_SECS);

// Shared state — passed DOWN from page.tsx as props
// (so both the home card and the sheet stay in sync)
overlayOpen: boolean;
onToggleOverlay: () => void;
nudgeLeft: number;
onNudgeLeftChange: (n: number) => void;
TSX
// useRef stores the timer ID without causing re-renders
const intervalRef = useRef<ReturnType<typeof setInterval> | null>(null);

intervalRef.current = setInterval(() => {
  secs--;
  setRemainingSecs(secs);    // update the countdown display
  if (secs <= 0) {
    clearInterval(intervalRef.current!); // ! = "I know this isn't null"
    if (newLeft > 0) setCooldownActive(false); // unlock nudge if pips remain
  }
}, 1000); // runs every 1000ms = 1 second
TSX
// Pip dots — filled if nudges remain, grey if used
{[3, 2, 1].map((pip) => (
  <span
    key={pip}
    style={{
      background: nudgeLeft >= pip ? '#EA580C' : 'rgba(0,0,0,0.1)',
    }}
  />
))}
// When nudgeLeft=2: pip 3 → grey (2≥3 false), pips 1&2 → orange
TSX
// e.stopPropagation() prevents click from bubbling up
// to the transparent button behind the overlay
const handleNudge = useCallback((e: React.MouseEvent) => {
  e.stopPropagation();
  // ...
}, [nudgeLeft, cooldownActive, onNudgeLeftChange]);

ChargingStationsCard.tsx

The "Charging Stations" card on the home screen. Contains the stat chips (Available / In Use / Earliest Free) and the spot list. It's a container — it receives all interaction handlers as props from page.tsx and passes them down to child components.

TSX
// Computed OUTSIDE the component — only runs once at module load
// because the data is static (no need to recompute every render)
const available = SPOTS.filter((s) => s.status === 'available').length;
const inUse = SPOTS.filter((s) => s.status === 'in-use').length;

// .filter() creates a new array with only matching items
// .length gives you the count
⚠️

Prop drilling: This component receives overtime state from page.tsx and passes it straight through to OvertimeCard — it doesn't use the overtime state itself. This is called prop drilling. Acceptable in small apps; larger apps use React Context to avoid it.

StationSheet.tsx

The full-screen slide-up panel showing all 10 spots. Structurally similar to ChargingStationsCard but with a drag handle, a collapse button, and each spot row uses .glass instead of a transparent background.

It exists as a separate component because it has different visual styling and different structural elements. Combining them into one component with lots of conditions would be harder to read.

TSX
// Toggling CSS classes drives the slide animation
<div
  className={`sheet-transition ${open ? 'sheet-expanded' : 'sheet-collapsed'}`}
>
// sheet-collapsed → transform: translateY(100%)  — hidden below screen
// sheet-expanded  → transform: translateY(0%)    — normal position
// sheet-transition → transition: transform 0.4s  — smooth animation

The "Soonest Available" popup. When the sheet is open, it centers on screen. When the sheet is closed, it floats 90px above the nav bar. This replicates the original mockup's positioning behavior.

OccupyModal.tsx

The "Occupy Spot" modal with time inputs and quick-select buttons. Uses local state for the hours/minutes inputs — no other component needs to know what the user is typing, so it stays local.

TSX
// Local state — only this modal cares about the time input values
const [hours, setHours] = useState('');
const [minutes, setMinutes] = useState('');

// Programmatically fill inputs from quick-select buttons
const setTime = (h: number, m: number) => {
  setHours(h === 0 ? '' : String(h)); // show placeholder if 0
  setMinutes(m === 0 ? '00' : String(m));
};

// Early return pattern — exit before doing anything if invalid
const confirm = () => {
  if (!hours && !minutes) {
    alert('Please enter a charge time.');
    return; // stops here — doesn't close the modal
  }
  onClose();
};

// Reset inputs when modal closes (so next open starts fresh)
const handleClose = () => {
  setHours('');
  setMinutes('');
  onClose();
};

How State Flows Through the App

In React, state flows in one direction — downward from parent to child via props. When a child needs to update something in the parent, it calls a function that was passed down as a prop. This is called the unidirectional data flow principle.

page.tsx (owns ALL shared state)
 │
 ├── sheetOpen ──────────────────→ StationSheet (controls visibility)
 │
 ├── freePanelOpen ────────────────→ EarliestFreePanel (controls visibility)
 │
 ├── occupyOpen + occupySpotId ──────→ OccupyModal (open + which spot)
 │
 ├── activeTab ───────────────────────→ BottomNav (which tab is lit)
 │
 ├── overtimeOverlayOpen ──┐
 │   overtimeResolved      ├──→ ChargingStationsCard ──→ OvertimeCard (ctx="collapsed")
     nudgeLeft             ┘
 │                             └──→ StationSheet ──→ OvertimeCard (ctx="sheet")
🔑

The key insight: OvertimeCard appears twice — once inside ChargingStationsCard and once inside StationSheet. Both instances share the same state from page.tsx. That's why nudging in the sheet also uses up a pip in the home card — they're looking at the same data.

Concepts Cheat Sheet — For Your Test

Concept What It Is When You Use It
Component A function that returns JSX Every UI element
Props Data passed into a component from its parent When a parent needs to configure a child
useState Data that changes over time — triggers re-render Interactive UI: open/closed, counts, form inputs
useCallback Memoizes a function so it isn't recreated every render When passing functions as props to children
useRef Holds a value that persists without triggering re-render Timer IDs, DOM element references
'use client' Marks a component as browser-only Whenever you use hooks or event handlers
Lifting state up Moving state to a common parent so siblings can share it Two components need the same data
Prop drilling Passing props through intermediary components Small apps — acceptable; larger apps use Context
{condition && …} Conditional rendering — shows element only if true Showing/hiding UI based on state
.map() in JSX Renders a list of elements from an array Spot rows, nav tabs, quick-select buttons
key prop Required on list items so React can track them Always when using .map() in JSX
interface Defines the shape of a TypeScript object Props definitions, data models
'a' | 'b' | 'c' Union type — value can only be one of these Status fields, tab names, variant props
Early return if (bad) return; — exit function before finishing Form validation, guard clauses
@/ alias Import alias for the project root Cleaner imports: @/lib/data instead of ../../lib/data
e.stopPropagation() Stops a click event from bubbling to parent elements When nested clickable elements overlap
children prop Special prop representing nested JSX content Layout components (layout.tsx wrapping every page)
export default The main thing a file exports (imported without braces) Every component file has one
named export Additional exports from a file (imported with braces) Types, utility functions, constants
